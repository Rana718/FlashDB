## Performance: Seqlock + Per-Key Spinlock

The concurrency model was redesigned from clone+CAS to zero-clone in-place mutation:

- **Before (v0.1.0):** `update_with` cloned the entire value, mutated the clone, then CAS-swapped. For collections (List with 10K items, Set with 100K members), each mutation cloned the entire structure — O(N) per operation. Under contention, CAS retries multiplied the cost. Result: 14GB memory, crashes on large collections.
- **After (v0.1.1):** Per-key spinlock serializes writers (nanosecond hold). Value mutated directly in-place. Seqlock counter lets iteration readers detect concurrent writes and retry safely. Zero clone, zero allocation on the write path.

| Metric | v0.1.0 | v0.1.1 |
|--------|--------|--------|
| LPUSH/RPOP | crashed | 31.9M ops/sec |
| SADD | crashed | 17.1M ops/sec |
| ZADD | crashed | 8.0M ops/sec |
| Peak RSS | 14 GB | 700 MB |
| Hot Key contention | ~15M ops/sec | 23.0M ops/sec |

## Authentication

- New `FYRODB_AUTH` env var — set a password, clients must AUTH before any command
- Zero overhead when disabled (single predicted-not-taken branch)
- Constant-time password comparison (timing attack resistant)

## Configuration

- Fixed dispatch fast-path missing LPOP, SADD, JSON.SET, JSON.GET
- Fixed JSON string parser allocating per-character for non-escaped strings
- Optimized spinlock with fast-path `swap` and `#[cold]` slow path
